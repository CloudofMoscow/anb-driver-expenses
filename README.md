# ANB Fleet Finance

Единая PWA-система для рейсов, расходов и финансового контроля автопарка.

## Что уже работает

- один вход с автоматическим открытием кабинета офиса или водителя;
- несколько сотрудников офиса и отдельные учётные записи водителей;
- тягачи, тралы, изменяемые сцепки и история их состава; назначенные, но ещё не начатые рейсы безопасно переназначаются вместе с новым составом;
- заказчики, несколько контактов и телефонов;
- назначение рейса со ставкой, НДС, способом и сроком оплаты, примерным адресом и несколькими точками разгрузки;
- изменение адреса и точек разгрузки до закрытия рейса с уведомлением водителя;
- закрытые для водителя ставка, заказчик и договор-заявка;
- начало и завершение рейса с обязательным оригиналом фотографии одометра;
- расходы водителя с обязательным комментарием и чеком;
- очередь действий водителя при временной потере связи с автоматической отправкой после восстановления интернета; отклонённая сервером команда блокирует зависимые действия до исправления, а ошибочный старт можно отменить вместе со всей зависимой цепочкой;
- настраиваемые категории, фактические дата и время расхода, проверка расходов и автоматическое обнаружение повторного чека;
- полный неизменяемый журнал проверки расхода: все решения офиса, ответы водителя и повторные проверки с автором и временем;
- полный журнал чеков каждого рейса без скрытого ограничения на последние операции;
- базовые флаги аномалий пробега и времени, а также исправление офисом до подтверждения с сохранением исходных значений в аудите;
- доплаты и штрафы без изменения первоначальной ставки;
- авансы, частичные и окончательные оплаты заказчика;
- задолженность и переплата заказчика;
- постоянные расходы сцепки, включая ежемесячный лизинг и распределение страховки на 12 месяцев;
- разовые расходы компании или конкретной сцепки с документом и обязательным комментарием;
- общие, индивидуальные и рейсовые ставки зарплаты и суточных;
- автоматическое начисление зарплаты по подтверждённому пробегу и суточных по календарным дням рейса, включая предварительный расчёт во время незакрытого рейса;
- один перевод водителю с распределением между зарплатой, суточными, авансом и компенсацией личного расхода;
- возвраты авансов, переплаты, ручные корректировки с обязательной причиной и сторно ошибочных переводов;
- автоматический взаиморасчёт «кто кому должен» для офиса; начисления, ставки, суточные и итог к выплате по умолчанию не передаются в кабинет водителя;
- уведомления водителю о новом/переназначенном рейсе, изменении маршрута, переводе, сторно, отклонённом расходе или запросе пояснений; открытые кабинеты обновляются автоматически;
- отчёт по прибыльности каждой сцепки за выбранный период, включая разбивку затрат, себестоимость и выручку на километр;
- управление доступом сотрудников, отзыв всех сессий, самостоятельная смена пароля и локальная очистка телефона водителя;
- сторно ошибочных переводов, оплат заказчиков, корректировок ставки, постоянных и разовых расходов без физического удаления истории;
- серверная история важных изменений;
- резервное копирование базы и закрытого файлового хранилища.

Файлы исходного локального прототипа `index.html` и `app.js` сохранены только как архив разработки и не выдаются рабочим сервером. Актуальные кабинеты находятся в `office.html` и `driver.html`.

## Локальный запуск

Требуется Node.js 24 или новее. Перед первым запуском установите зафиксированные зависимости:

```powershell
npm install
npm start
```

Откройте `http://127.0.0.1:8787`. При первом рабочем запуске задайте как минимум:

```text
NODE_ENV=production
ANB_BOOTSTRAP_LOGIN=...
ANB_BOOTSTRAP_PASSWORD=...
ANB_ORGANIZATION_NAME=ANB Group
```

Расчёт зарплаты и суточных является офисным. Водительский API и интерфейс по умолчанию его не получают. Зарезервированный переключатель `ANB_DRIVER_COMPENSATION_VISIBLE=1` сохраняет возможность вернуть водительский раздел позднее после отдельного решения владельца; в рабочем запуске сейчас его задавать не нужно.

Web Push включён по умолчанию. При первом запуске сервер один раз создаёт VAPID-ключи и сохраняет их в SQLite, поэтому резервная копия базы сохраняет и идентичность push-отправителя. Для рабочего домена желательно указать реальный контакт `ANB_VAPID_SUBJECT=mailto:...`. Переключатель `ANB_DISABLE_PUSH=1` предназначен только для диагностики. На публичном адресе PWA и Push API требуют HTTPS; пользователь включает уведомления отдельной кнопкой в своём кабинете.

Рабочие данные по умолчанию сохраняются вне OneDrive в `%LOCALAPPDATA%\ANB Fleet Finance\data`. Путь можно явно изменить через `ANB_DATA_DIR`. Известный демонстрационный пароль запрещён в обычном запуске; готовый безопасно отделённый пример запускается только командой ниже.

При запуске за reverse proxy приложение по умолчанию слушает только `127.0.0.1`. Для контейнера можно задать `ANB_HOST=0.0.0.0`. Публичный доступ должен идти только по HTTPS. Заголовок `X-Forwarded-For` учитывается только при явном `ANB_TRUST_PROXY=1`; такой режим намеренно разрешён лишь при loopback-привязке Node-сервера за доверенным reverse proxy. Сервер также ограничивает время заголовков, полного запроса и число запросов на одном соединении.

Общий лимит закрытого файлового хранилища компании по умолчанию — 20 ГБ. Его можно изменить через `ANB_ORGANIZATION_UPLOAD_LIMIT_MB`. Это предохранитель от случайного заполнения диска, а не замена наблюдению за свободным местом.

## Готовая демонстрация

Демо использует отдельную папку `demo-data/` и не меняет рабочую базу из `%LOCALAPPDATA%\ANB Fleet Finance\data`.

```powershell
npm run demo
```

На Windows можно также запустить `start-demo.ps1`. Затем откройте `http://127.0.0.1:8787`.

```text
офис:     owner / anb-demo-2026
водитель: driver1 / driver-demo-2026
```

В демонстрации уже есть 5 водителей, 5 сцепок, заказчики, рейсы в разных статусах, чеки, выплаты, задолженность и расходы компании.

## Проверка

```powershell
npm test
npm run check
```

Интеграционные тесты проходят весь основной сценарий: офис создаёт автопарк и рейс, водитель прикрепляет фото и расходы, отвечает на запрос пояснения, офис проводит проверку, исправляет ошибочный пробег, начисляет зарплату и суточные, распределяет смешанный перевод, учитывает аванс и получает итоговую прибыль. Отдельно проверяются невозможные даты, повторная отправка финансовых команд, перенос состава, права ролей, закрытые файлы, отзыв сессий, уведомления, сторно, старые миграции и переносимая резервная копия.

## Резервная копия

```powershell
npm run backup
```

Копия SQLite и оригиналов файлов создаётся по умолчанию в `%LOCALAPPDATA%\ANB Fleet Finance\backups`. Внутри копии пути к файлам переносимые: каталог копии можно восстановить как единое целое. Перед сообщением об успехе проверяются наличие, размер и SHA-256 каждого вложения; неполная копия удаляется и команда завершается ошибкой. Для реальной эксплуатации копию необходимо автоматически переносить на другой зашифрованный диск или в приватное объектное хранилище и периодически проверять восстановление.

## Архитектурные решения первого этапа

- SQLite в режиме WAL — минимальная стоимость и отсутствие отдельного администратора БД для пяти водителей;
- суммы хранятся целыми копейками;
- документы и чеки не публикуются как статические ссылки, загружаются потоково, ограничены по типу, параллельности, суточному и общему объёму и выдаются только после серверной проверки роли; старые непривязанные загрузки очищаются автоматически;
- рабочий запуск не создаёт известные реквизиты; пароли хешируются `scrypt`, проверка выполняется асинхронно, вход ограничен по паре «аккаунт + IP», по IP и по числу одновременных проверок;
- важные финансовые команды имеют стабильный ключ повторной отправки и на сервере, и в форме офиса, поэтому даже потерянный HTTP-ответ не удваивает сумму или приложенный документ;
- финансовые корректировки записываются отдельными событиями, а не перезаписывают исходные суммы;
- в каждой записи есть `organization_id`, поэтому схема готова к последующему переходу на PostgreSQL и нескольким компаниям.

База должна находиться на локальном диске сервера, не в OneDrive и не в сетевом каталоге. GitHub Pages подходит только для старого статического прототипа: новая система требует постоянно работающий Node-сервер.

## Следующие этапы

После проверки текущего контура на реальных рейсах: внутренние сообщения между офисом и водителем, импорт конкретного топливного сервиса, OCR одометра и договоров, проверка QR/ФНС, банковский импорт и подготовка многокомпанийского SaaS. Push уже использует собственный сервер, а запись в базе и in-app синхронизация остаются резервным каналом при недоступности системной доставки.
